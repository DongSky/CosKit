# CosKit 1.0.0-beta.7 — P0 性能与可靠性验证

日期：2026-10-09；Windows x64。本报告对应 CKPipe 共享存储、资源预算和大图交互三个 P0。测试使用本机 NVIDIA GeForce RTX 4090，数据仅代表该机器和下述工作负载。

## 实现

- CKPipe schema 2：当前文档和全部版本共享内容寻址的压缩像素块；版本描述符保留完整图层树、蒙版、精度、ICC 和参数。兼容读取 schema 1，并在记录/保存时迁移。
- 原生工程保存、记录版本、恢复在后台执行。任务绑定原文档；取消、失败、文档切换及并发新增对话不能覆盖新状态。关闭窗口必须等保存成功。
- 每个版本保存独立的小尺寸浮点预览，浏览版本无需反复解码完整图像。预览纹理按字节和项数限制，并按可见使用更新淘汰顺序。无法编码可选预览时仍保存原始文档。
- 所有打开文档共享历史预算；持久工程块、效果缓存与预览预算计入分配。GPU 按全部打开文档的像素/历史及工程数据调整缓存；System Info 和 MCP `ui_inspect.resources` 可查看分项。
- 大图整像素平移：独立目标块在原生端并行复制，保留原始编码样本；整块位移仍共享原块，WASM 和小区域使用顺序路径。
- 记录版本仅使工程元数据变脏，不提高像素修订号，避免不必要的全画布刷新。

## 测量方法

CKPipe：同一份 5472 × 3648 分层照片，新建一层，6 次固定种子的局部笔刷与版本记录，然后保存、重开、恢复。通过各版本的完整文档结构和原始样本对比检查一致性；原照片不被修改。`scripts/bench-ckpipe.py` 用 MCP 重现工作负载，依赖 Python `psutil` 采样进程 RSS。该 fixture 属于用户私有测试数据，不随发布包提供。

交互：原版 beta.6 与 beta.7 的 release `perf_scenarios` 在本机连续运行相同参数 `--reps 3`。每个常规场景报告 3 次采样的中位数和最大值（3 次样本的 p95 接近最大值，不用于长期稳定性保证）；24 MP 内容识别缩放按工具约定只有一次采样。GPU 等待完成后计时。

## 同机测量结果

Windows 11，24 个逻辑处理器，约 62.8 GiB 可用物理总内存，RTX 4090。编译与文件语料测试结束后，先运行 beta.6，再运行 beta.7；CKPipe 每版本各完成一轮，含操作系统文件缓存和 20 ms RSS 采样的影响，不作为所有机器的性能保证。

| CKPipe 工作负载 | beta.6 | beta.7 | 减少 |
|---|---:|---:|---:|
| 工程大小（MiB） | 870.196 | 130.302 | 85.0% |
| 保存（秒） | 6.572 | 0.705 | 89.3% |
| 重开（秒） | 3.782 | 2.055 | 45.7% |
| 恢复 v1（秒） | 1.925 | 0.907 | 52.9% |
| 首次记录版本（秒） | 0.727 | 0.487 | 33.0% |
| 后续 5 次记录中位数（秒） | 0.817 | 0.182 | 77.7% |
| 整个工作流峰值 RSS（MiB） | 3203.270 | 1191.133 | 62.8% |

文件实际字节数为 912,467,033 → 136,631,620。6 个版本逐一恢复后，完整 Document（剔除 pipeline、统一文件显示名与文档 ID）相等，涵盖图层、原始像素、ICC 和位深；始终为 **5472 × 3648、RGB/8**。跨 RGB/Gray/CMYK/Lab 与 8/16/32f 的无损平移由合成回归测试覆盖。

| 大图操作（p50，ms） | beta.6 | beta.7 | 减少 |
|---|---:|---:|---:|
| 全画布带阴影图层拖动 | 120.54 | 104.11 | 13.6% |
| 全画布图层拖动 | 52.84 | 39.99 | 24.3% |
| 15000 × 10000、16 位图层移动 | 237.92 | 219.07 | 7.9% |
| 32 位、20 图层文档移动 | 24.97 | 22.04 | 11.7% |
| 24 MP 内容识别缩放（单次） | 12212.39 | 12247.88 | -0.3% |

31 个场景均无执行错误。全套耗时 35.3 → 35.7 秒，说明本次优化集中在工程存储和像素平移，不能声称全部操作加速。全套进程峰值 RSS 为 2004.8 → 2066.2 MiB（增加约 3.1%）；并行路径没有带来所有工作负载的内存下降。CMYK 笔刷因初测波动单独复测 15 次：p50 4.56 → 4.95 ms，最大值 37.79 → 38.18 ms；仍有轻微开销及尾部停顿。24 MP 内容识别缩放约 12.2 秒、带阴影拖动约 104 ms，以及后台模糊场景约 270 ms 的最大帧耗时仍是后续优化项。

完整前后 GPU 场景数据单独保存在 `native/perf/coskit-windows-beta7.json`；没有覆盖上游 M4 Pro 基线。

## 可靠性与桌面验证

- 修改涉及的 crate 测试合计 **2896 项通过、24 项默认忽略**。首次完整运行中的一个新增关闭等待 UI 测试缺少字体初始化，补齐测试上下文后独立重跑通过；其余测试没有失败。
- 发布模式 IO/PSD/PSB/TIFF/HEIF 等文件语料检查：**353 项通过、2 项默认忽略**。
- 严格 Clippy、29 crate 分层、WASM、627/627 菜单 parity、异常参数 panic hunt 均通过；最终 release 桌面与 CLI 构建成功。
- 桌面打开上述真实照片工程；后台 checkpoint/save 返回任务 ID。保存约 641 ms，6 次 UI 检查往返 25–31 ms，帧号由 19 持续增长至 44。这里是 MCP 控制往返时间，不是画布帧耗时。
- 保存后 dirty 清除；取消 checkpoint 得到 cancelled；目录外写入被拒绝、文件未生成且文档继续 dirty；随后合法保存成功。关闭等待的测试覆盖成功才关闭、失败或取消保留文档。
- 6 个持久预览缓存约 2.25 MiB，低于本次 64 MiB 预算。原生窗口和 System Info 截图已检查，尺寸状态与缩略图正常。截图和私有工程仅保存在本机 `test_output/p0/`。

## 复现

在仓库根目录（文件语料与私有 fixture 已准备好）：

```powershell
python scripts/bench-ckpipe.py --executable dist/CosKit_1.0.0-beta.6_x64_portable/coskit-cli.exe --label before-final
python scripts/bench-ckpipe.py --executable native/target-release/release/photocraft-cli.exe --label after
native/target/debug/examples/compare_ckpipe.exe test_output/p0/before-final.ckpipe test_output/p0/after.ckpipe
test_output/p0-before-perf.exe --reps 3 --json test_output/p0/windows-before-final.json
native/target-release/release/examples/perf_scenarios.exe --reps 3 --json test_output/p0/windows-after.json
```

`p0-before-perf.exe` 是本次修改前冻结的本机 release 基准。测试文件与基准二进制不会随产品包分发；公开源码可生成新的同平台基线。


## 使用边界

内存设置是可回收缓存和历史的预算，不是整个进程的硬限制。当前像素、最近一次撤销、持久版本和临时后台缓冲可能超过预算；压缩版本池尚未换出到磁盘。GPU 保留 512 MiB 最小工作预算。不会为达成预算自动删版本、缩小画布或降低位深。

旧文件没有嵌入预览时，首次查看相应版本仍需后台解码。参数重放目前仍同步。保存取消若发生在原子提交之后，磁盘可能已经得到完整捕获版本，编辑器仍保留未保存标记；不会出现半份工程。

新版 schema 2 工程需 beta.7 或更新版读取。原 `.pcraft`、PSD/PSB 交换能力和 PhotoCraft 贡献致谢继续保留。
