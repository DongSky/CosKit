# CKPipe 工程格式（schema 2，CosKit 1.0.0-beta.8）

`.ckpipe` 是完整 CosKit 工程：原生可编辑图层、参数化编辑记录、项目对话、harness 决策与审核记录，以及可恢复的分支版本存放在一个文件中。PSD/PSB 继续用于 Photoshop 交换，PCraft 保持兼容。

## 使用

在底部版本条和对话侧栏的工程面板操作：

1. 用「记录版本」命名一个基准，例如「开始修肤色前」。
2. 正常手工编辑或只向自主修图输入目标。编辑命令和参数自动记录。通过审核的自主工作流提交时自动建立前后版本。
3. 用「保存工程…」保存 `.ckpipe`。新文档的“另存为”默认该格式；已有 PSD/PCraft 的“保存”仍遵从其原格式。
4. 重开 `.ckpipe` 后恢复图层、当前画面、项目对话与版本。重复保存会增加有变化的版本；相同画面和操作位置复用已有快照。
5. 点击旧版本「恢复」，当前画面先建立保护版本，旧版本之后的分支不会删除。恢复和参数重放均可整体撤销/重做。
6. 版本条「参数」中先选择基准版本，再选编辑记录，使用滑杆、曲线等控件修改参数后重放；复杂参数仍可使用高级 JSON。也可在工程面板给出多条步骤。所有步骤在隔离后台任务执行，全部成功才应用为新版本。

PSD 与普通图片不保存 CosKit 对话和版本；需要完整工程时保存 `.ckpipe`。本版写出的 PCraft 也可保留扩展项目字段和已有版本，但不自动建立保存版本；旧 PhotoCraft 可能忽略扩展字段并在重存时丢失它们。

## 数据布局

运行时版本与对话保存在独立的文档会话中，不改变像素文档的共享引用或预览取消事务；在保存、恢复和工作流边界与图层合并。JSON 使用浮点往返精确解析，保留参数数值。

复用经过现有格式测试的 PCraft ZIP 容器、浮点/16 位通路、原子写入和 BLAKE3 + zstd 对象存储；不通过 PSD 中间转换当前图层。

```text
manifest.json
  format_version: 1                    原生容器版本
  document.*                           全部原生图层/蒙版/通道/路径/ICC/位深/文档数据
  document.pipeline
    state.schema: 2                    CKPipe 项目协议版本
    state.head                         当前分支的基准版本 ID
    state.versions[]                   id、parent、label、snapshot、operation_count、图层目标
    state.operations[]                 command、params、base、active_layer、selected_layers、replayable
    state.conversations[]              role、text、document、conversation
    state.runs[]                       自主规划、工具参数、审查、问题、回退和完成记录
    state.omitted_operations           超过记录限额的操作计数（面板明确提示）
    snapshots: {hash: blob_hash}        版本描述符索引
    objects: {path: {hash, bytes}}       跨版本共享压缩块及校验
    previews: {snapshot: blob_hash}      独立的小尺寸浮点预览
blobs/<hash>.zst                        ICC、PSD 原始块、智能对象、版本描述符和预览等
tiles/<hash>.zst                       当前图像和历史版本共享的分块数据
```

schema 2 的版本描述符包含不带 pipeline 的原生 manifest 和排序后的对象路径列表。当前文档与所有历史版本共用内容寻址的 zstd 数据块；只改变图层属性不会重复存储原图像素，局部笔刷只增加改变的块。仍禁止递归工程。恢复使用完整原始精度，不依赖生成模型或缩略图。

读取兼容 schema 1 的完整 PCraft ZIP 快照；下次记录/保存版本时自动迁移到共享块，不覆盖旧文件直到原子写入成功。新版工程应使用 beta.7 或更新版打开，beta.6 不识别 schema 2。版本预览保存 384 像素长边的工作空间浮点复合及 ICC，显示时走当前显示器色彩转换。旧文件缺少预览时只在后台解码被请求的版本。打开工程不会执行记录里的命令。

`head` 是当前工作分支的基准，未记录成版本的手工修改仍保存在当前文档树中。普通撤销改变画面，不删除项目审计、对话或已存版本。生成调用具有随机性，恢复使用已存像素；重新生成应发起新的自主工作流。

## 参数重放边界

可重放原生调整、滤镜、选区、图层属性和普通笔刷笔迹。笔刷记录包含实际笔尖/动态参数、颜色、大小、流量、透明度、种子和压力轨迹，避免依赖下一次启动的默认笔刷。目标图层必须存在于所选基准中。

新建图层、文字/路径结构操作、复杂混色/历史画笔等仍有命令记录及完整快照，但不自动重放；跨版本新建对象 ID 的自动重映射未实现。文件、脚本、模型调用、外部色彩配置和跨文档取样不能在参数重放中执行。不是对任意历史节点自动重新计算所有下游结果的节点式编辑器。

## MCP

沿用真实 MCP 的 `command_run`，可通过 `command_list` 发现：

- `coskit.project.inspect {}`：项目版本、命令参数、对话和工作流记录（不返回二进制快照）。
- `coskit.project.checkpoint {"label":"Before lighting"}`。
- `coskit.project.restore {"version":"v1"}`。
- `coskit.project.replay {"version":"v1","steps":[{"command":"image.adjustments.invert","params":{}}]}`。
- `coskit.project.annotate {"document":ID,"messages":[...],"run":{...}}`：项目级记录写入，不改变异步 AI 使用的像素修订号。
- `doc_save {"path":"photo.ckpipe"}` / `doc_open {"path":"photo.ckpipe"}`。

保存使用同样的授权目录约束。重放继承调用会话的命令授权，并拒绝外部文件参数。没有 API key、服务配置、控制令牌或 `.env` 的自动打包入口。工程包含用户对话和图像，分享文件也会分享这些内容。

## 限制与恢复

每个工程最多 256 个版本、100000 条命令、10000 条对话、1000 次工作流；旧版单个快照最多 1 GiB；新版版本描述符最多 32 MiB，共享对象、描述符及预览合计最多 2 GiB，容器不使用 ZIP64。达到版本上限时明确报错，需另开新工程整理历史；不会静默丢弃版本。单条过大命令不保存参数并增加遗漏计数，但最终图层快照仍保留。原生桌面的工程保存、记录版本和恢复通过后台任务执行，支持进度和取消；CLI 默认等待任务完成。beta.8 起参数重放也通过后台任务执行，支持进度与取消。

任务绑定原文档；切换标签不会将结果写入另一个文档。失败或取消不会把当前文档标为已保存，关闭窗口会等待保存成功。工作期间新增的对话或图像状态不会被旧任务覆盖。取消发生在文件原子提交之后时，磁盘可能已保存完整捕获版本，但编辑器仍保留未保存状态；文件不会被写成半份。

性能设置的内存额度由所有打开的文档共享，扣除版本压缩块、预览和效果缓存后分配历史预算。预览纹理最多 24 项，另有 4–64 MiB 字节预算；历史超额会淘汰最旧撤销状态。当前像素、最近一次撤销、持久版本和临时任务缓冲不能被强行丢弃，因此这是缓存/历史预算，不是进程 RSS 的硬上限。持久版本目前保留在内存中，尚无磁盘换出。GPU 根据全部打开文档和工程数据的占用调整缓存，仍有 512 MiB 最小工作预算。

未来版本号、损坏哈希、缺失快照、非法父子关系、递归快照和解压超限都会报错。原文件通过原子替换保护；失败重放不修改当前画面。恢复工程不自动恢复仍在运行的网络请求，harness 中途候选检查点仍仅在内存中。

历史功能测试见 `beta4-validation.md`；beta.7 性能和可靠性验证见源码仓库 `docs/p0-performance.md`。


beta.8 的可视化参数窗口、原尺寸同步对比及差异图见 [P1 说明](p1-harness-and-review.md)。
